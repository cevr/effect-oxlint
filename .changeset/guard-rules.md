`noGlobals` follows every hop of the global object to itself: a page's `top`, `parent` and `frames`, a chain of its own names (`globalThis.window`, `window.top`), and `document.defaultView`, so `parent.fetch()` and `document.defaultView.setTimeout()` are reported. A watched global held where the walk cannot follow it (`{ w: window }`, `[document]`, `() => performance`, `mine ?? globalThis`, a `return`) is now reported as a use; handing it to a call stays allowed, since that is how an adapter is built over it. `members` takes a list of bans for one global, so its members can name different replacements, and a configured ban's `use` is named before the built-in one.

New recommended rule `noPointFreeLog`: a logger that prints every argument it is given (`console.log`, `info`, `warn`, `error`, `debug` and `trace`, effect's `Console` members of the same names, and `Effect.log`, `logFatal`, `logError`, `logWarning`, `logInfo`, `logDebug` and `logTrace`) handed point-free to a callback that is passed an index prints the index after each line; call it in a callback, `(line) => Console.log(line)`. The calls that pass an index are `Effect.forEach`, `Effect.filter` and `Effect.partition`, effect's `Array` module, and an array literal's methods; any other effect module's callback (`Exit.map`, `Option.map`) passes one value and is not reported. A method of the same name on a receiver the rule cannot see (`xs.map(console.log)`) is reported with what prints if `xs` is an array. `console.count`, `time`, `table` and `dir` take a label, a column filter or options and are not reported.

New opt-in rule `requireSpawnBudget`: a test (`it`, `test` and their variants from `bun:test`, `effect-bun-test`, `vitest`, `@effect/vitest` or the global) whose body starts a process (Bun's `spawn`/`spawnSync`, `node:child_process`) or makes an effect `ChildProcess` command (`ChildProcess.make`, which starts a process when the command runs), itself or through a function of the same file, names its timeout: a number after its body, or `{ timeout }` in its options before the body (Vitest's `it(name, { timeout }, body)`) or after it. The report says which the test does. `minimum` also reports a timeout the rule reads as a number below it.
